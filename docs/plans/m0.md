# M0 as built: the homelab prototype

Written 16 Oct 2026, after the fact. **The plan for M0 is `docs/brief.md`** (Nejc's build brief, 14 Oct); there were no step-by-step build plans as there are for M1 (`m1.2.md`–`m1.5.md`). This page doesn't restate the brief. It says what was built for each milestone, where the build departed from the brief and why, what later milestones changed, and what the brief left open that is still open. The reasons are in `docs/decisions.md`; the D-numbers below point there.

Main reader: whoever moves Annex from the homelab VM to AWS.

## Where the build departed from the brief
| The brief said | What was built | Why | D |
|---|---|---|---|
| Apps built and run through the `annex-vm` Docker context, with the Mac's Compose | Everything over `ssh annex` with the VM's Compose; the context is optional | Compose reads `env_file` on the client, so app secrets would have had to pass through the Mac; one transport is simpler | D1 |
| One `edge` network for Traefik and everything it routes | `annex-edge` (Traefik, apps, gateway) plus an internal `annex-platform` for the platform UIs | Dozzle trusts `Remote-User` from whoever calls it; on a shared network an app could read every log | D2 |
| A socket proxy "per permission level if needed" | Two: read-only (Traefik, Homepage, Dozzle) and exec (Ofelia, backup) | The exec proxy is root-equivalent; accepted for the prototype | D4 |
| Backup on the `appdata` network | Not on it: dumps run inside appdata-db as an exec hook | It only needs the files | D11 |
| Strip `Remote-*` before forward-auth | Done on the entrypoint for every router, plus an explicit deny for non-admins on admin hosts | An app can't be exposed without login by mistake; a missing deny let non-admins fall through to the catch-all | D5 |
| Browser access through the `dronky` route | Through an SSH tunnel on port 8443, `ANNEX_PUBLIC_PORT`, `/etc/hosts` lines | The route was never decided; port 443 on the Mac was taken | D6 |
| (not in the brief) | Config changes force a recreate (config hashes); Authelia 256 MiB and `GOMEMLIMIT`; Metabase keeps its own login; platform tiles are static | Found while building | D7–D9, D13, D20 |
| Apps "non-root, cap_drop ALL, read-only where the template allows" | Every app as uid 10001, read-only root, `/tmp` tmpfs, no capabilities, 256 MiB / 0.5 CPU, for every app; the deploy refuses root images | One fixed uid lets `/data` be chowned once | D16 |
| `scripts/wipe-vm.sh` returns the VM to empty, and bootstrap plus push bring it back | Written, **never run** | Not worth the risk on the demo VM; it happens with the AWS move (Nejc, 16 Oct) | D15, D58 |
| Claude Code builds `vibe-dashboard` from an empty folder (M0.4) | Not recorded as a separate run; part of the demo | | D29 |

## What M1 and the review changed in M0's parts
- **Deploys** (D17): every deploy is a numbered release with a health gate and automatic rollback; the image is built before the switch (D30, D31).
- **Contract:** v1 adds `notify`, `alerts.to`, `webhooks` and `resources.memory`, and documents any stack, not only the templates (D33). `LOG_LEVEL` and the logging convention come in M2.1.
- **Demo users:** still generated by bootstrap, but accounts are now managed with `annex users`. Invitations go out by email, users can reset and change their own password, and the user directory follows Authelia's file (D57).
- **Mail:** the brief had none; M1.2 added Mailpit and annex-ops, and Authelia now sends its emails there too (D57).
- **Ofelia's restart on schedule changes** (D18) stays. Gatus's similar workaround (D41) goes away in M2.6.
- **Tests:** the M0 suites now share `scripts/testlib.sh`. `test-smoke.sh` is the quick check after a push; `test-all.sh` runs everything (D58).
- **Demo:** an honest line about what the AI can't do, and a rollback moment (D58).

## What the brief left open, and where it stands
| Open in the brief | Status (16 Oct) |
|---|---|
| The browser route through `dronky` (domain, TLS, access from outside the LAN) | Still open; the tunnel and hosts lines (or the optional wildcard resolver, setup.md §3) serve the demo |
| Production front door and mapping its identity headers to `Remote-*` | Annex's own accounts are the default now (D57); a company SSO can sit in front later without app changes. Not built |
| Coolify vs this CLI as the deploy backend | Not revisited. The CLI grew releases and rollback (M1.1) |
| Per-app network isolation, enforced egress | Not built. Several "any app on `annex-edge` can …" acceptances are listed in D36, D44, D46; the console (M2.4) is kept off app networks by design |
| Connectors (n8n or alternatives) and their licensing | On hold (Nejc, 16 Oct). M1.5 covers incoming webhooks only |
| Lovable apps with Supabase backends | The contract's "Bring your own stack" covers moving a Lovable export onto the `static` server; no worked example yet |
| A narrower deploy path than root-equivalent SSH | Not built. "Human only" actions are enforced by the CLI and the MCP's tool list, not by the server (D58) |

## For the AWS move
- **Do the round trip M0 skipped:** from an empty machine, `bootstrap.sh`, `push.sh`, then `test-smoke.sh` and, with Nejc's go-ahead, `test-all.sh`. M1 added state that only a fresh install exercises: `annex_ops.sql`, the directory, the hooks secrets, the receiver's role.
- **Things tied to this homelab that won't carry over as they are:** the SSH jump host, `ANNEX_PUBLIC_PORT=8443` and the tunnel, mkcert, Mailpit (SES instead), backups on the VM's own disk (S3 instead).
- **Things that rely on the host being Ubuntu:** `python3-yaml` for `annex users` (D57).
