# M1.2 implementation plan: annex-ops, email (Mailpit) and Slack

For a build agent. Written 15 Oct 2026 against commit `bc7b39a` (M1.1 done). The milestone comes from Nejc's M1 plan (section "4. Sending email", "5. Slack" and "Shared foundation: annex-ops"); this file is the how, and is complete on its own.

**Read first:** `CLAUDE.md`, `docs/brief.md` (ground rules), `docs/decisions.md` (D1–D32), and this whole file. Do only M1.2. Stop when it's done and report to Nejc; don't start M1.3.

## Goal
Apps can send email and Slack messages with one HTTP call, without holding any SMTP password or bot token:
- `POST $ANNEX_OPS_URL/v1/email`, `POST $ANNEX_OPS_URL/v1/slack`, with `Authorization: Bearer $ANNEX_OPS_TOKEN`.
- An app declares what it needs in `annex.yaml` (`notify:`); its token can do exactly that and nothing else.
- Email goes only to company addresses; every send is logged (app, recipients, subject, time, result), bodies are never stored.
- In the prototype, mail goes to **Mailpit**, so nothing leaves the VM. Its web UI is behind login, admins only.

This milestone also lays the foundation that M1.3 (alerts), M1.4 (usage) and M2 (log shipping, console, audit) build on: the `ops` service, its database, and the `docker exec` admin command the CLI uses. Keep the code split into small modules so those can be added later; don't build any of them now.

## Done when (acceptance, from the M1 plan)
1. `annex run monthly-report monthly` emails "your report is ready, here's the link" to `cm`, and the message shows up in Mailpit.
2. An external recipient is rejected with a clear error, and nothing is sent.
3. `monthly-report` can post to its declared Slack channel; posting to any other channel is refused. (Without a Slack workspace, see decision 1: the refusal is tested, and delivery returns a clear "not connected" error.)
4. Every send and every rejected send appears in `annex sends <app>`, without the body.
5. `scripts/test-notify.sh` passes, and so do all earlier suites: `test-platform.sh`, `test-apps.sh`, `test-jobs.sh`, `restore-test.sh`, `test-rollback.sh`.

## Decisions already made for you
These are defaults chosen when this plan was written. Log each in `docs/decisions.md` (what, why, alternatives).
1. **Slack without a workspace.** Build the Slack endpoint, the manifest channel allowlist and real delivery through `chat.postMessage`. If no bot token is configured, an allowed post returns **503** with a message saying Slack isn't connected yet, and the send is logged as `unavailable`. Delivery is tested for real only once Nejc adds a token (setup.md step, below).
2. **Mailpit's UI is admins only** (`kaldi-admin`): it shows everyone's mail.
3. **Allowed recipient domains** come from the setting `ANNEX_EMAIL_DOMAINS`, default `annex.example` (the demo users' domain). Exact extra addresses go in `ANNEX_EMAIL_ALLOW` (empty by default; in production the client approves each).
4. **Recipients can be logins** (`"cm"`), resolved to their email from the user directory. Apps know logins from `Remote-User`, so this is the natural form.
5. **One built-in template, `notice`** (title, body, optional link). Real templating is Goat Mailer's job in production.
6. **Rate limits per app:** 60 emails and 60 Slack posts per hour (settings `OPS_EMAIL_PER_HOUR`, `OPS_SLACK_PER_HOUR`).
7. **No attachments.** A request with `attachments` gets a 400 that says to link to the file in the app instead.
8. **In `monthly-report`, a failed email fails the job; a failed Slack post only prints a warning.** The email is the point of the monthly run; Slack is optional while there's no workspace.
9. **Schema by idempotent SQL, not a migration framework.** `db/appdata/annex_ops.sql` is applied by `push.sh` on every push, like `db/product/api_views.sql`. Later milestones append to it.

## How the pieces fit
```
app container ──HTTP, Bearer token──▶ ops:8000 (annex-edge)
                                         │  checks token → app_grants (annex_ops DB in appdata-db)
                                         │  logs every attempt → annex_ops.sends
                                         ├─SMTP──▶ mailpit:1025 (annex-platform) ──UI──▶ Traefik ▶ mail.<domain> (admins)
                                         └─HTTPS─▶ slack.com/api/chat.postMessage (only if a token is set)
annex deploy ─▶ annex_vm.py provision ─▶ ops token in secrets/apps/<app>/ops_token, grant row in annex_ops.app_grants
annex sends  ─▶ ssh annex docker exec annex-ops-1 python -m annex_ops.ctl sends --json
```

## Step 1. Secrets, settings and the user directory
**`vm/bootstrap-secrets.sh`**
- `master.env` is only written when missing, so an existing VM never gets new keys. Add a helper that appends a key only if it's absent, and use it for the existing keys and a new one: `APPDATA_DB_OPS_PASSWORD` (`rand`).
- Write `$S/ops.env` (mode 600) on every run:
  `OPS_DATABASE_URL=postgres://annex_ops:<APPDATA_DB_OPS_PASSWORD>@appdata-db:5432/annex_ops`
- Write the user directory on every run, **without password hashes**, to `$D/state/directory/users.json`:
  `{"sam": {"name": "Sam Novak", "email": "sam@annex.example", "groups": ["builders"]}, ...}` from the existing `USERS` array (use `jq -n` or plain printf; jq is on the VM). Mount the *directory* into containers, never the single file: rsync and `mv` replace the inode and a single-file bind mount goes stale (D7).
- Create `$D/state/mailpit` in the `mkdir -p` line.

Run `scripts/bootstrap.sh` (idempotent; it never replaces existing secrets) and check that `master.env` gained the key and nothing else changed.

**Settings** (`.env.example` with comments, passed through `scripts/render.py` `derive()` into the platform `.env`):
- `ANNEX_EMAIL_DOMAINS=annex.example` (comma-separated)
- `ANNEX_EMAIL_ALLOW=` (comma-separated exact addresses)
- `ANNEX_EMAIL_FROM=noreply@annex.example`

`derive()` only outputs keys it names, so add these three explicitly.

## Step 2. The annex_ops database
**`db/appdata/annex_ops.sql`**, idempotent, run as `postgres` with `-v ops_pw=...`:
- Role `annex_ops` (LOGIN, password `:'ops_pw'`), created if missing, password always re-set.
- Database `annex_ops` owned by `annex_ops` (create via `SELECT ... \gexec` as `annex_vm.py` does); `REVOKE CONNECT ... FROM PUBLIC`.
- `\c annex_ops`, `SET ROLE annex_ops`, then:
```sql
CREATE SCHEMA IF NOT EXISTS annex_ops;
-- what each app's token may do; written by annex_vm.py provision
CREATE TABLE IF NOT EXISTS annex_ops.app_grants (
  app            text PRIMARY KEY,
  token_sha256   text NOT NULL UNIQUE,
  email          boolean NOT NULL DEFAULT false,
  slack_channels text[] NOT NULL DEFAULT '{}',
  updated_at     timestamptz NOT NULL DEFAULT now()
);
-- every send attempt; never the body (M2's audit view reads this)
CREATE TABLE IF NOT EXISTS annex_ops.sends (
  id         bigserial PRIMARY KEY,
  ts         timestamptz NOT NULL DEFAULT now(),
  app        text NOT NULL,              -- '_platform' for platform alerts (M1.3)
  channel    text NOT NULL CHECK (channel IN ('email', 'slack')),
  recipients text[] NOT NULL,            -- resolved addresses, or the Slack channel
  subject    text,                       -- email only
  status     text NOT NULL CHECK (status IN ('sent', 'rejected', 'failed', 'unavailable')),
  error      text
);
CREATE INDEX IF NOT EXISTS sends_app_ts ON annex_ops.sends (app, ts DESC);
```
`annex_vm.py` writes `app_grants` as `postgres` (superuser), which is fine.

**`scripts/push.sh`** applies the file **before** the full `up`, because ops's healthcheck needs the database and `up --wait` would otherwise time out on the first push:
1. `docker compose up -d --wait appdata-db`
2. apply `annex_ops.sql`: on the VM, source `secrets/master.env` and pipe `/srv/annex/platform/db/appdata/annex_ops.sql` into `docker compose exec -T appdata-db psql -v ON_ERROR_STOP=1 -U postgres -d postgres -v ops_pw="$APPDATA_DB_OPS_PASSWORD" -f -`. The password stays on the VM. If the key is missing, stop with "run scripts/bootstrap.sh first".
3. the existing `docker compose up -d --build --wait ...` for everything.

Keep `annex_ops.sql` in `db/appdata/`, not in `db/appdata/init/` (that folder only runs on a fresh database).

The nightly backup already dumps every database (`db/appdata/hooks/dump-all.sh`), so `annex_ops` is covered with no change.

## Step 3. The ops service
Code in `ops/` at the repo root, built on the VM from the synced bundle (it's the first platform image built from source).

```
ops/
  Dockerfile
  requirements.txt          # fastapi==0.143.0, uvicorn==0.54.0, psycopg[binary]==3.3.6 (same pins as the templates)
  annex_ops/
    __init__.py
    config.py               # all settings from env, with defaults; one place
    db.py                   # connect() via OPS_DATABASE_URL; one short-lived connection per request is enough
    directory.py            # users.json → login → {name, email, groups}; re-read when the file's mtime changes
    auth.py                 # Bearer token → sha256 → app_grants row, or 401
    sends.py                # log_send(), recent_count(app, channel) for rate limits, list_sends()
    email.py                # request model, recipient resolution, the notice template, SMTP; send_email() for internal use too
    slack.py                # request model, channel check, chat.postMessage via urllib; post_slack() for internal use too
    app.py                  # FastAPI app: routes, error handler
    ctl.py                  # admin commands for `docker exec`: sends, grants, info
  tests/                    # pytest, pure functions only, no DB or network
```
- **Dockerfile:** `FROM python:3.13.16-slim-trixie`, `PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1`, `pip install --no-cache-dir -r requirements.txt`, copy `annex_ops/`, create user 10001, `USER 10001`, `CMD ["uvicorn", "annex_ops.app:app", "--host", "0.0.0.0", "--port", "8000"]`.
- **Slack** uses `urllib.request` and **SMTP** uses `smtplib`: no extra dependencies.
- **Internal functions** `send_email(app, ...)` and `post_slack(app, channel, text)` skip the token check but still validate recipients and log the send. M1.3's alerts will call them with `app="_platform"`.

**`compose.yaml`**, service `ops` (container `annex-ops-1`, hostname `ops`):
- `build: {context: ./ops, labels: {com.kaldi.annex: "true"}}`, `image: annex-ops:local`, the `x-base` anchor.
- `env_file`: `${ANNEX_DATA_DIR}/secrets/ops.env`, plus `{path: ${ANNEX_DATA_DIR}/secrets/slack.env, required: false}` (Compose ≥ 2.24 supports this; the VM has v5.6).

- `networks: [edge, platform, appdata]`: edge so apps reach it (and for outbound HTTPS to Slack; `platform` and `appdata` are internal), platform for Mailpit's SMTP, appdata for its database.

## Step 5. The API
All errors are JSON `{"error": "<what's wrong and how to fix it>"}`. Install an exception handler so FastAPI's own `{"detail": ...}` and its 422 validation errors come out in the same shape, as 400 with a readable message (field and problem), not pydantic's raw list.

| Method, path | Auth | Does |
|---|---|---|
| `GET /healthz` | none | 200 `{"ok": true}` if the DB answers, else 503 |
| `GET /v1/me` | token | `{"app", "email": bool, "slack_channels": [...], "slack_connected": bool}`, for debugging |
| `POST /v1/email` | token | send one email |
| `POST /v1/slack` | token | post one Slack message |

**Auth:** `Authorization: Bearer <token>` → `sha256(token)` → `app_grants`. Missing or unknown: 401 "missing or unknown ANNEX_OPS_TOKEN. Declare notify: in annex.yaml and deploy again; Annex injects the token".

**`POST /v1/email`**
```json
{"to": ["cm", "sam@annex.example"], "subject": "Report ready",
 "text": "...", "html": "...", "template": "notice", "data": {"title": "...", "body": "...", "link": "https://...", "link_text": "Open"}}
```
- `to`: string or list, 1–20 entries. An entry without `@` is a login, resolved from the directory; unknown → 400 naming the known logins. An address must be in `ANNEX_EMAIL_DOMAINS` or `ANNEX_EMAIL_ALLOW`; otherwise **403** "Annex only sends to company addresses (annex.example). x@gmail.com is outside. If the client approves it, the platform team adds it to ANNEX_EMAIL_ALLOW". **All or nothing:** if any recipient is rejected, nothing is sent.
- `subject`: 1–200 characters, no newlines.
- Exactly one of `text`, `html` or `template` (400 otherwise). `html` also gets a plain-text part (tags stripped). Body at most 256 KB (413).
- `template: "notice"` with `data` `{title, body, link?, link_text?}`: renders a simple inline-styled HTML email plus text. Escape every value with `html.escape`. Only `link` values starting with `https://` or `http://` are allowed. Unknown template → 400 listing the templates.
- `attachments` (any value) → 400 "Attachments aren't supported. Store the file in /data and email a link to it in your app: it stays behind login and downloads are logged". Any other unknown field → 400 naming the allowed fields.
- Rate limit: count of `sent` rows for this app and channel in the last hour ≥ `OPS_EMAIL_PER_HOUR` → 429 saying when it resets.
- Not granted (`email = false`) → 403 "this app may not send email: add notify: {email: true} to annex.yaml and deploy again".
- Sending: `From: "<app> via Annex" <ANNEX_EMAIL_FROM>`, header `X-Annex-App: <app>`, via SMTP to `OPS_SMTP_HOST:OPS_SMTP_PORT`. SMTP failure → 502 and status `failed`.
- Response 200: `{"id": <sends.id>, "to": ["cm@annex.example", ...]}`.
- Every attempt that gets past auth is logged in `sends`, including rejections (with the reason in `error`). Never store the body.

**`POST /v1/slack`**
```json
{"channel": "#finance-reports", "text": "Report ready: https://...", "blocks": [ ... ]}
```
- `channel` must be exactly one of the app's granted channels (compare lower-cased) → else **403** "this app may post only to: #finance-reports. Add the channel under notify.slack in annex.yaml and deploy again".
- `text` or `blocks` required (`text` is required by Slack as the notification fallback when `blocks` is set; require it whenever `blocks` is given).
- Order of checks: auth, channel, rate limit, then **connected?** If `SLACK_BOT_TOKEN` is unset → **503** "Slack isn't connected on this Annex yet, so nothing was posted. Send an email instead, or ask the platform team to connect Slack" and status `unavailable`.
- Connected: POST `https://slack.com/api/chat.postMessage` (`OPS_SLACK_API` overrides the base URL) with JSON and the bot token. Slack answers 200 with `"ok": false` on errors: map them to 502 with a fix where obvious (`not_in_channel` → "invite the Annex app to #x in Slack"; `channel_not_found` → "the channel doesn't exist or is private").

**`ctl.py`** (run with `docker exec annex-ops-1 python -m annex_ops.ctl <cmd> [--json]`):
- `sends [--app X] [--limit 50]`: newest first; no bodies exist to show.
- `grants`: apps and what they may do (never tokens or hashes).
- `info`: `{"email": "smtp mailpit:1025", "slack_connected": bool, "domains": [...]}`.

**Unit tests** (`ops/tests/`, run on the Mac without the VM):
```bash
uv run --python 3.13 --with-requirements ops/requirements.txt --with pytest pytest ops/tests -q
```
Cover recipient resolution (logins, domains, allow list, all-or-nothing), the notice template (escaping, link schemes), request validation (exactly one body field, attachments message, unknown fields), Slack channel matching, and the rate-limit decision. Keep DB and network out of these functions so they're testable.

## Step 6. Contract, manifest and provisioning
**Manifest** (`cli/src/annex_cli/manifest.py`):
```yaml
notify:                      # optional
  email: true                # may send email through ANNEX_OPS_URL
  slack: ["#finance-reports"]  # channels it may post to
```
- New `KNOWN_KEYS` entry `notify`; validate it's a mapping with only `email` (bool) and `slack` (list of `#name`, regex `^#[a-z0-9][a-z0-9_-]{0,79}$`). Errors say how to fix, e.g. "notify.slack: 'finance' must start with '#', e.g. '#finance'".
- New `Manifest` fields `notify_email: bool = False` and `notify_slack: list[str] = field(default_factory=list)`. **They must have defaults**: `Manifest.from_dict` loads manifests of older releases for rollback (D30), and those don't have the keys. A rollback to such a release must then revoke the grant, which the defaults give you for free.
- Add `ANNEX_OPS_URL` and `ANNEX_OPS_TOKEN` to `INJECTED_ENV`.

**`vm/annex_vm.py provision`:** new arguments `--notify-email` and `--slack "#a,#b"` (validate channel names again with the same regex).
- If either is set: `secret_file(sdir / "ops_token", 32)`, upsert `app_grants` (token hash, email, channels) in DB `annex_ops`, and put `ANNEX_OPS_TOKEN` in the env file.
- If neither: delete the grant row and the token file (like the gateway role when views go away).
- If the `annex_ops` database doesn't exist and a grant is requested → `Fail("annex-ops isn't set up on this server: run scripts/bootstrap.sh and scripts/push.sh")`. If nothing is requested, skip silently.
- `deprovision`: delete the grant row (if the DB exists); the token file goes with the secrets directory.
- Stays stdlib-only, prints JSON, never prints the token.

**`cli/src/annex_cli/ops.py`:**
- One helper builds the `provision` arguments from a manifest, used by `_activate`, and from `deploy.json`, used by `secret_set`. Add `notify_email` and `notify_slack` to the record `_write_record` writes, and read them with `.get(..., default)` in `secret_set` (older records don't have them).
- `compose_for`: `ANNEX_OPS_URL=http://ops:8000` in `environment` when notify is set (the token stays in the env file). Add it to `injected_env` in the deploy result.
- **Warnings:** deploy returns a `warnings` list, and the CLI prints them after "is live". First warning: `notify.slack` is declared but Slack isn't connected (ask `ctl info`; if ops isn't reachable, skip the check). M2 will add more warnings to the same list, so keep it generic. The MCP's `annex_deploy` returns the list as part of the result already.
- New `sends(app=None, limit=50)` op and `annex sends [app] [-n 50]` command (table: time, channel, recipients, subject, status, error). Not exposed over MCP in M1.2.
- `status`: show `notify` (email yes/no, Slack channels).

**`contract.md`** (it's also `docs/app-contract.md`, a symlink): the `notify:` key in the manifest example; the injected variables; a short "Email and Slack" runtime rule: only through `ANNEX_OPS_URL`, never an SMTP server or Slack token of your own; the two endpoints with their JSON; recipients (logins or company addresses, all or nothing, no attachments); the limits; and that errors say what to fix. Add `annex sends` to the commands table.

5. From inside client-lookup, a request with no token and one with a made-up token → 401.
6. `annex sends monthly-report --json`: the email is `sent` to `cm@annex.example`; the rejections are there with reasons; no row has a body field.
7. `annex_ops.app_grants` (via `docker exec annex-appdata-db-1 psql -d annex_ops`) has monthly-report and not client-lookup.
8. Mailpit's UI: `kaldi-admin` 200, `sam` 403.

Then run every suite. **Known flake:** right after a deploy that restarts Ofelia, `test-platform.sh` reports Ofelia as "health: starting" for up to 30 s. Wait until `annex-ofelia-1` is healthy before running it; it's not a regression.

## Pitfalls (each of these has bitten or nearly bitten before)
- `appdata-db` init scripts run only on a fresh database; this VM's database exists. Hence the idempotent SQL applied by `push.sh`.
- `master.env` is never rewritten; new keys need the append-if-missing helper.
- `push.sh` rsyncs with `--delete`: anything not in the rendered bundle disappears from the VM.
- Compose doesn't notice changed bind-mounted files; `render.py` hashes `config/<service>` (D7). The ops image rebuild recreates ops by itself; Authelia and Homepage changes are already hashed.
- `annex_vm.py` runs with the VM's stock `python3`, stdlib only.
- Older `releases.jsonl` manifests and `deploy.json` records lack the new fields: always default them.
- Apps run read-only as uid 10001; so does ops. Nothing may write outside `/tmp`.
- Never print tokens, hashes or email bodies, in logs, `ctl` output or errors.
